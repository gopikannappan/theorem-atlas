# Brocard–Ramanujan research attempt

Goal: investigate new positive integer pairs satisfying n!+1=m², while retaining the possibility that none exist beyond (4,5),(5,11),(7,71). This is a bounded exploratory attempt, not a promise to solve the open problem. The unrestricted question remains open unless a separately reviewed proof or counterexample is obtained.

## Predeclared scope and budget

One exact baseline checks every n from0 through2000 with full integer factorials and isqrt. A separate large-value experiment checks exactly10000 consecutive n in the inclusive interval [2^61-10001, 2^61-2]. This is a narrow interval near a large Mersenne prime, **not all values up to that number**. It was selected for cheap exact modular evaluation, not because of evidence that it contains a solution. Novelty of this range is not established.

Use32 distinct primes strictly above the interval, generated by SymPy1.14.0. Fully factored Lucas-style primality certificates are generated for them and checked by a separate standard-library-only program; the checker does not rely on SymPy's primality answers. There is one research attempt with180 seconds for search plus certificate checking, seven targeted tests, and30 seconds for the generic Lean lemma. Checkpoint and retain artifacts even if interrupted. No adaptive search expansion or probabilistic acceptance.

If a value survives every modular test, record it as **unresolved**. Passing residue tests does not identify a square or a new solution. Computing the full factorial for a surviving n near2^61 is infeasible within this budget; any survivor would require a new bounded plan.

## Mathematical reduction

For a prime p>n, let T=(n+1)(n+2)...(p-1). Wilson's theorem gives n!T≡-1(mod p), so n!≡-T⁻¹(mod p). The tail is short when n is close to p, even when n itself is enormous. If n!+1 is a quadratic nonresidue modulo this prime, it cannot be an integer square.

The search computes one tail product and inverse per prime at the lower endpoint, then updates factorial residues forwards by multiplication. It stores the first rejecting prime index for every n, or -1 for an unresolved value. The checker reconstructs backwards from (p-1)!≡-1 using one inverse per step and checks the assigned Euler nonresidue witness. It verifies exact interval coverage and never treats an unresolved entry as excluded. Both paths use the same mathematical Wilson/Euler reductions, so they are not independent mathematical proofs.

Primality certificate: factor p-1 completely into certified primes q. Supply a with a^(p-1)≡1(mod p) and gcd(a^((p-1)/q)-1,p)=1 for every distinct q. For any prime divisor r of p, these conditions force the multiplicative order of a modulo r to be p-1. Hence p-1 divides r-1, so r≥p; therefore p is prime. The base case is2. This standard argument and Wilson/Euler remain dependencies of the computational checker, not fully Lean-instantiated proofs here.

## Additional proof reduction to investigate

For n≥4, any solution has odd m, and writing a=(m-1)/2 and b=(m+1)/2 gives ab=n!/4, b-a=1, and gcd(a,b)=1. Consequently each entire prime-power factor of n!/4 must go wholly into a or wholly into b. Conversely, consecutive positive factors a,b of n!/4 give m=a+b and m²=n!+1. This is a standard factorization reformulation, **not a new proof or a completeness argument**. Excluding all such partitions for every n>7 is still missing; a random-gap or growth heuristic cannot fill that gap.

## Formal scope and trust

ModularObstruction.lean is a small original generic lemma checked with Lean4.34.1 and bundled Std (no Mathlib): a non-square residue obstruction for an arbitrary natural N rules out N=m*m. It reuses Nat.mul_mod and Nat.mod_lt. It does not define or alter factorial, weaken the Brocard problem, certify the search interval, prove Wilson's theorem, instantiate primality witnesses, or resolve the open conjecture.

Its short proof serves as a transparent local mathematical component for a future certificate-to-Lean bridge; no novelty is claimed. Existing formalizations and published results should be linked/reused before developing a larger proof. Independent statement-fidelity and trust review remain pending. No catalogue theorem is marked audited.

Python tests check forged primality certificates, incomplete coverage, preservation of known solutions, unresolved-result handling, and exact small residue comparisons. Additional exhaustive small-prime tail tests compare the search formula with direct factorials. Python/SymPy computations are not end-to-end Lean verification.

## Sources and provenance

- [Berndt and Galway, On the Brocard–Ramanujan Diophantine equation n!+1=m², Ramanujan Journal4 (2000),41–42](https://doi.org/10.1023/A:1009873805276): established computational/quadratic-residue approach. This project claims no new sieve idea or improvement over their published search bound.
- [Bravo, On Brocard's problem with Padovan and Perrin numbers, 2026](https://arxiv.org/html/2606.28577v1): current context, known pairs and restricted variants. Its restricted result does not settle the general problem.
- [SymPy number-theory documentation](https://docs.sympy.org/latest/modules/ntheory.html): generation/factorization tooling. SymPy1.14.0 and mpmath1.3.0 are pinned; package archives, apt packages and runner infrastructure are not fully hash-pinned.
- [Existing formal-search example](https://prove2.me/theorems/0c3596cd-9424-4454-8a22-671854bf8c2d): discovery lead only; its artifacts and acceptance status were not independently checked or copied.

Original research code is Apache-2.0. Source proofs and papers remain linked. No external manuscript/proof was copied into this attempt. The Lean archive and Ubuntu image are pinned by SHA256/digest in Dockerfile. Proof and computation execution are offline, non-root, resource-bounded and read-only apart from a dedicated artifact mount. Build-time dependency fetching has no repository credentials.

## Reproduction

Run the Bounded Brocard-Ramanujan research GitHub Actions workflow on this PR/branch. Its exact Docker build, offline tests, search/checker commands and Lean command are in .github/workflows/brocard-research.yml. Source code is pinned by the workflow commit and copied into the container. All execution is remote; nothing runs on the user's machine.

Results and the exact certificate are checkpointed in ATTEMPTS.md and results/. An eighth test replays the committed certificate and checks its hash. Any bounded exclusion is a computational observation with explicit trust dependencies, not a proof of global completeness or human-equivalent audit.
